# Loop runbook — 批量生成26个K线策略独立App，共享数据源，一致UI风格

> A runnable closed-loop design generated by loop-constructor. Follow it as a loop: make a small change → run the stage check → read the result → fix → repeat until the check passes, then advance.
> **Altitude:** medium — 顺序依赖阶段，单agent执行，爆炸半径中等（新目录不影响现有代码），可逆性高

## Hard constraints
- Minimal viable change; don't touch unrelated files.
- Don't change public APIs / add deps without justification.
- No production resources.
- On a requirement contradiction → STOP and report.

## Why this shape (decision log)
> The D0–D6 selection procedure that derived this loop's shape.
- **D0** (loop) — 每个App可用tsc+test机器验证done?
- **D1** (staged (4 seams)) — shared→template→26apps→test，每阶段产出可检查制品
- **D2** (plan_execute_verify×3 + review×1) — 各阶段有计划但需验证；最后阶段为整体审查
- **D3** (on_the_loop) — blast中等×reversibility高×feedback好，门控处人工确认
- **D4** (medium) — 阶段间有依赖，顺序执行
- **D5** (每阶段max=3，外层max=4) — 失败时loopback到上游阶段
- **D6** (iteration_first) — tsc/test秒级反馈，可频繁验证

## Stages (run in dependency order; each stage is its own gated loop)
> After a stage gate goes green, commit/checkpoint it; on a loopback, reset to the last green checkpoint rather than editing forward.

### Stage 1 — `extract_shared`  ·  pattern: plan_execute_verify

- **Done when:** shared/目录包含indicators/、services/、database/、components/，且每个模块可独立import
- **Check (run — the gate):** `cd kline-strategy-apps && npx tsc --noEmit --project shared/tsconfig.json`  ·  expect: `pass`
- **Falsifiable when:** shared模块有类型错误或导入路径不正确
- **Passing-but-wrong (ruled out):** tsc通过但运行时import失败（如循环依赖）——需后续阶段验证
- **Depends on:** — (entry stage)  ·  admit downstream only once this check passes.
- **Stop:** max 3 iterations; failure branches:
    - 共享模块抽取后tsc持续报错
- **On failure:** escalate.

### Stage 2 — `create_template`  ·  pattern: plan_execute_verify

- **Done when:** app-template/目录包含完整App骨架，npx tsc --noEmit通过，expo start可启动
- **Check (run — the gate):** `cd kline-strategy-apps/app-template && npx tsc --noEmit && npm test`  ·  expect: `pass`
- **Falsifiable when:** 母版App有类型错误或测试失败
- **Passing-but-wrong (ruled out):** tsc通过但UI交互逻辑错误——需人工在Expo Go验证
- **Depends on:** `extract_shared`  ·  admit downstream only once this check passes.
- **Stop:** max 3 iterations; failure branches:
    - 母版App tsc或测试失败
- **On failure:** loop back to `extract_shared`.

### Stage 3 — `batch_generate`  ·  pattern: retry

- **Done when:** 26个App目录全部创建，每个App的tsc --noEmit通过
- **Check (run — the gate):** `cd kline-strategy-apps && for /d %i in (app-*) do (cd %i && npx tsc --noEmit && cd ..)`  ·  expect: `pass`
- **Falsifiable when:** 任一App有类型错误或导入失败
- **Passing-but-wrong (ruled out):** 所有App tsc通过但策略逻辑未正确注入——需测试阶段验证
- **Depends on:** `create_template`  ·  admit downstream only once this check passes.
- **Stop:** max 3 iterations; failure branches:
    - 连续3个App生成失败
- **On failure:** loop back to `create_template`.

### Stage 4 — `batch_test`  ·  pattern: review

- **Done when:** 26个App全部npm test通过，expo start可启动
- **Check (run — the gate):** `cd kline-strategy-apps && for /d %i in (app-*) do (cd %i && npm test && cd ..)`  ·  expect: `pass`
- **Falsifiable when:** 任一App测试失败或无法启动
- **Passing-but-wrong (ruled out):** 测试通过但策略逻辑错误——需人工在Expo Go验证交互
- **Depends on:** `batch_generate`  ·  admit downstream only once this check passes.
- **Stop:** max 3 iterations; failure branches:
    - 超过50%App测试失败
- **On failure:** loop back to `batch_generate`.

## Stop conditions (overall)
- **Success:** 26个App全部tsc通过+test通过+Expo Go可启动
- **Max iterations (budget cap):** 4
- **Failure branches:**
  - 母版App设计有根本性缺陷需重新设计
- **Escalate to a human when:**
  - 连续3轮失败
  - 母版App测试不通过

## Terminal states
- **SUCCESS** — 26个App全部tsc通过+test通过+Expo Go可启动 → done.
- **STOPPED_UNMET** — a max-iteration cap is hit or a failure branch fires: stop, report the last green stage and the unmet gate, hand back the partial diff, do NOT merge. Never relax a gate to force a pass.
- **ESCALATE** — one of the escalate triggers above fires: hand to a human.

## Human placement
- on_the_loop

## Checker (separate, fresh-context)
- 验证26个App的策略逻辑正确性、UI一致性、交互友好性

## Risk guards
- **共享模块导入路径错误** → 抽取后立即tsc验证
- **策略逻辑注入失败** → 每个App生成后验证策略配置文件
- **26个App依赖版本不一致** → 统一package.json模板
- **UI风格不一致** → 统一theme/colors.ts和组件库

## Harness primitives
- typescript (tsc --noEmit)
- jest (npm test)
- expo start (Expo Go调试)
- node scripts批量生成
