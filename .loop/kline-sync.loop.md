# Loop runbook — 为离线K线App增加联网获取最新K线并与本地db对比、手机端实时补齐的闭环（三源降级，前复权，全量，仅WiFi，后台定时）

> A runnable closed-loop design generated by loop-constructor. Follow it as a loop: make a small change → run the stage check → read the result → fix → repeat until the check passes, then advance.
> **Altitude:** medium — 单体开发、顺序门控阶段、单 agent；爆炸半径中等（仅新增模块+向用户db INSERT新行），可逆性高（git+导入自动备份），阶段间有依赖无独立扇出

## Hard constraints
- Minimal viable change; don't touch unrelated files.
- Don't change public APIs / add deps without justification.
- No production resources.
- On a requirement contradiction → STOP and report.

## Why this shape (decision log)
> The D0–D6 selection procedure that derived this loop's shape.
- **D0** (loop) — 可机器判定：对每只股票断言 MAX(local date) 覆盖至最新交易日且无缺失bar，SQL/断言可跑
- **D1** (staged (5 seams)) — KlineFetcher(可独立测)→diff/patch(依赖fetcher+db)→UI(依赖sync服务)→background(依赖sync服务)→集成质检，每层交稳定可校验产物
- **D2** (plan_execute_verify + 末段 review) — 各阶段方案明确但需中途中止校正（复权不一致/三源全挂）；集成段为正确性审查
- **D3** (on_the_loop) — 爆炸半径中×可逆性高×反馈质量好(测试可抓坏)；仅在门控处人工复核，不每轮介入
- **D4** (medium) — 阶段间有依赖（diff依赖fetcher、UI/background依赖sync），无独立扇出
- **D5** (每阶段max_iterations≤8 + on_failure escalate；外层max_iterations 4 + 失败分支) — 受控重试+失败升级+复权不一致整体中止
- **D6** (completeness_first) — App需整体连贯，检查(tsc/test)成本中等，每阶段做完整再校验；低cap、plan_execute_verify、集成跑全量测试

## Stages (run in dependency order; each stage is its own gated loop)
> After a stage gate goes green, commit/checkpoint it; on a loopback, reset to the last green checkpoint rather than editing forward.

### Stage 1 — `scaffold`  ·  pattern: plan_execute_verify

- **Done when:** 新增 src/services/KlineFetcher.ts、src/services/SyncService.ts、scripts/verify_sync.js、WB改动清单.md，且 npx tsc --noEmit 通过
- **Check (run — the gate):** `cd kline_-analysis && npx tsc --noEmit`  ·  expect: `pass`
- **Falsifiable when:** 若 KlineFetcher.ts/SyncService.ts 有类型错误或引入未定义符号，tsc 退出非0
- **Passing-but-wrong (ruled out):** tsc 通过但模块未真正实现抓取/补齐逻辑（仅空壳）——需后续单测把关
- **Depends on:** — (entry stage)  ·  admit downstream only once this check passes.
- **Stop:** max 8 iterations; failure branches:
    - tsc 持续报错超过重试上限
- **On failure:** escalate.

### Stage 2 — `fetcher`  ·  pattern: plan_execute_verify

- **Done when:** KlineFetcher 三源降级(腾讯→新浪→东财)可解析日K，且 fallback 顺序正确
- **Check (run — the gate):** `cd kline_-analysis && npx jest src/services/KlineFetcher.test.ts`  ·  expect: `pass`
- **Falsifiable when:** 若某源解析错误或 fallback 顺序错（如东财先于腾讯），对应断言失败
- **Passing-but-wrong (ruled out):** 测试只断言‘返回非空’而未断言来源优先级与字段映射，可能放过错源
- **Depends on:** `scaffold`  ·  admit downstream only once this check passes.
- **Stop:** max 8 iterations; failure branches:
    - 单测持续失败超过上限
- **On failure:** escalate.

### Stage 3 — `diff_patch`  ·  pattern: plan_execute_verify

- **Done when:** 对本地kline_daily按(code,date)比对，仅INSERT缺失bar且不复权/不改历史
- **Check (run — the gate):** `cd kline_-analysis && npx jest src/services/SyncService.test.ts`  ·  expect: `pass`
- **Falsifiable when:** 若实现改写了已有行或漏插缺失bar，断言(本地行数仅增、无UPDATE、缺失bar存在)失败
- **Passing-but-wrong (ruled out):** 测试未校验复权基准一致性，可能接受尺度错乱的INSERT
- **Depends on:** `fetcher`  ·  admit downstream only once this check passes.
- **Stop:** max 8 iterations; failure branches:
    - 单测持续失败超过上限
- **On failure:** escalate.

### Stage 4 — `ui`  ·  pattern: plan_execute_verify

- **Done when:** Overview/设置页新增‘一键补齐’按钮+进度+补齐摘要，tsc与eslint通过
- **Check (run — the gate):** `cd kline_-analysis && npx tsc --noEmit && npx eslint . --ext .ts,.tsx`  ·  expect: `pass`
- **Falsifiable when:** 若新增组件有类型错误或lint违规，tsc/eslint退出非0
- **Passing-but-wrong (ruled out):** 编译通过但按钮未真正调用SyncService——需集成测试把关
- **Depends on:** `diff_patch`  ·  admit downstream only once this check passes.
- **Stop:** max 8 iterations; failure branches:
    - tsc/lint持续失败超过上限
- **On failure:** escalate.

### Stage 5 — `background`  ·  pattern: plan_execute_verify

- **Done when:** expo-background-fetch注册定时补齐任务，含仅WiFi守卫与首次手动授权
- **Check (run — the gate):** `cd kline_-analysis && npx tsc --noEmit && npx jest src/services/BackgroundSync.test.ts`  ·  expect: `pass`
- **Falsifiable when:** 若任务未注册或WiFi守卫逻辑反了，类型/断言失败
- **Passing-but-wrong (ruled out):** 注册存在但未校验仅在WiFi下执行
- **Depends on:** `diff_patch`  ·  admit downstream only once this check passes.
- **Stop:** max 8 iterations; failure branches:
    - tsc/单测持续失败超过上限
- **On failure:** escalate.

### Stage 6 — `integration_gate`  ·  pattern: review

- **Done when:** 全量测试+类型+lint通过，且对样例db断言补齐后无重复主键、日期连续、缺失bar为0
- **Check (run — the gate):** `cd kline_-analysis && npx jest && npx tsc --noEmit && node scripts/verify_sync.js`  ·  expect: `pass`
- **Falsifiable when:** 若样例db补齐后出现重复主键或仍有缺失bar，verify_sync.js断言失败
- **Passing-but-wrong (ruled out):** 全量测试绿但verify_sync仅查行数未查日期连续性
- **Depends on:** `ui`, `background`  ·  admit downstream only once this check passes.
- **Stop:** max 4 iterations; failure branches:
    - 集成验证持续失败超过上限
- **On failure:** escalate.

## Stop conditions (overall)
- **Success:** db内每只股票kline_daily覆盖至最新交易日，缺失bar=0，全量测试/lint/类型通过，且无重复主键/日期断点
- **Max iterations (budget cap):** 4
- **Failure branches:**
  - 复权基准与db不一致→整批中止
  - 三源全挂的股票被跳过并记错
  - 连续3轮失败→暂停诊断
- **Escalate to a human when:**
  - 复权基准不一致
  - 连续3轮失败

## Terminal states
- **SUCCESS** — db内每只股票kline_daily覆盖至最新交易日，缺失bar=0，全量测试/lint/类型通过，且无重复主键/日期断点 → done.
- **STOPPED_UNMET** — a max-iteration cap is hit or a failure branch fires: stop, report the last green stage and the unmet gate, hand back the partial diff, do NOT merge. Never relax a gate to force a pass.
- **ESCALATE** — one of the escalate triggers above fires: hand to a human.

## Human placement
- on_the_loop

## Checker (separate, fresh-context)
- 正确性(仅INSERT新行/不复权/复权对齐)与需求覆盖(三源降级/全量/仅WiFi/后台定时)

## Risk guards
- **奖励黑客/测试过拟合** → 单测断言结果(行数增量、无UPDATE、来源优先级)而非代理(token)
- **错误放大(某源坏响应污染)** → 解析前校验schema，失败即切下一源
- **权限爆炸半径(写用户db)** → INSERT-only不变量+导入即备份旧库
- **复权尺度错乱** → batch级复权基准校验，不一致整体拒绝
- **上下文漂移/令牌膨胀** → 阶段化提交，每阶段独立可校验产物
